# คู่มือแปลเกมเป็นภาษาไทย — ความรู้ที่ได้จากโปรเจกต์นี้

สรุปจากการทำมอดแปลไทยสามเกม: How Many Dudes? (GameMaker, 2,348 ข้อความ, ปล่อยบน Nexus),
DiceVaders (Unity 6, 1,575 ข้อความ) และ Bewitching Sinners (Ren'Py 8, 22,042 ข้อความ)
เขียนให้หยิบไปใช้กับเกมหรือแอปอื่นได้ ไม่ผูกกับเกมใดเกมหนึ่ง

> อ่านหัวข้อ 1 ก่อนเสมอ ถ้าข้ามไปทำงานแปลเลยโดยยังไม่พิสูจน์เรื่องการแสดงผล
> มีโอกาสสูงที่จะแปลเสร็จแล้วพบว่าตัวอักษรแสดงผลผิด แล้วต้องรื้อใหม่ทั้งหมด

---

## 0. ลำดับงานที่ถูกต้อง

```
1. spike การแสดงผล   <-- ทำก่อนแปลแม้แต่ข้อความเดียว
2. ยืนยันช่องภาษา / ช่องทางใส่ข้อความ
3. วางคลังศัพท์ (glossary)
4. สร้างไปป์ไลน์แปล + ตัววาลิเดต
5. แปลเป็นชุด
6. build + ทดสอบในเกมจริง
7. แพ็กและปล่อย
```

**ข้อผิดพลาดที่แพงที่สุดคือสลับ 1 กับ 5** งานแปลเป็นงานที่ย้อนกลับมาแก้ยากที่สุด
ส่วนงานฟอนต์เป็นงานที่ค้นพบปัญหาช้าที่สุด จึงต้องเอางานฟอนต์ขึ้นก่อน

## 1. การแสดงผลภาษาไทย — ส่วนที่ยากจริง

### 1.1 ทำไมภาษาไทยพังในเอนจินเกม

ภาษาไทยซ้อนเครื่องหมายได้ถึง 3 ชั้นบนพยัญชนะตัวเดียว:

```
ที่  =  ท + สระอีบน + ไม้เอก
        base + upper vowel + tone mark
```

เอนจินเกมจำนวนมาก **ไม่เรียก OpenType shaping** วาดทีละ glyph ตามลำดับ code point
ผลคือวาด mark ความกว้างศูนย์ได้แค่ **ตัวเดียว** ต่อพยัญชนะหนึ่งตัว
วรรณยุกต์ที่มาหลังสระบนจึง **หายไปเฉย ๆ**

อาการอีกแบบคือวรรณยุกต์ไป **ทับ** สระบนพอดี อ่านเป็นคนละคำ

### 1.2 ชุดทดสอบที่ใช้จับปัญหานี้

ใส่ข้อความนี้เข้าเกมตั้งแต่วันแรก ครอบคลุมทุกเคสที่พัง:

```
ที่  ปี่  ฝี  ฟี  เป็น  กั๊ก  ญี่ปุ่น  เพื่อ  สิ้น  ที่นี่  ผู้  ปู่  ฟู่
```

- `ที่ ปี่` — วรรณยุกต์หลังสระบน (เคสที่พังบ่อยที่สุด)
- `ป ฝ ฟ` — พยัญชนะมีหาง วรรณยุกต์ต้องเลื่อนไปขวา ไม่งั้นทับหาง
- `ปู่ ผู้` — สระล่างกับวรรณยุกต์บนพร้อมกัน
- `กั๊ก` — ไม้ไต่คู้กับไม้ตรี

**ถ้าตัวใดตัวหนึ่งแสดงผิด แปลว่าเอนจินไม่ทำ shaping ต้องไปหัวข้อ 1.3**

### 1.3 ทางแก้ — อบ glyph ล่วงหน้าเข้า Private Use Area

แนวคิด: ถ้าเอนจินวาด mark ได้ตัวเดียว ก็ทำให้ mark ทั้งกลุ่มกลายเป็น glyph เดียวซะ

```
ตอน build:
  1. หา run ภาษาไทยในข้อความ  (regex ช่วง U+0E00 ถึง U+0E7F)
  2. ส่งเข้า HarfBuzz เพื่อ shape จริง  (uharfbuzz)
  3. ได้ตำแหน่ง dx, dy ของทุก mark ที่ถูกเลื่อน
  4. วาด base 1 glyph + mark ทั้งหมดรวมเป็นอีก 1 glyph
     โดยย้ายแต่ละส่วนไปตามตำแหน่งที่ HarfBuzz คำนวณ
  5. ยัด glyph ที่อบแล้วลง Private Use Area (U+E000 ขึ้นไป)
  6. แทนข้อความเดิมด้วย code point PUA
```

ผลคือเอนจินวาดแค่ 2 glyph ต่อพยางค์ ซึ่งมันทำได้ และตำแหน่งถูกเพราะ HarfBuzz คำนวณให้แล้ว

จุดที่ต้องระวัง:

- **ปิดฟีเจอร์ kern และ dist** ตอน shape ไม่งั้นระยะจะเพี้ยนเมื่อเอนจินวาดเอง
- **snap offset เล็ก ๆ ทิ้ง** (ราว 2.4% ของ em) ไม่งั้น glyph งอกเป็นพันตัวโดยไม่จำเป็น
- **เช็กว่า PUA ช่วงไหนว่าง** ฟอนต์บางตัวใช้ PUA อยู่แล้ว (PT Sans Narrow ใช้ U+F4xx)
- ถ้า glyph ที่ได้คือ base เดี่ยวไม่ถูกเลื่อน ไม่ต้องสร้าง PUA ใช้ code point เดิมได้เลย

### 1.4 OS/2 Windows metrics — ตัวที่ทำให้วรรณยุกต์หัวขาด

หลังรวมฟอนต์แล้ว **ต้องขยาย usWinAscent และ usWinDescent** ให้ครอบ glyph ใหม่

เอนจินจำนวนมาก clip ทุกอย่างที่อยู่นอกกรอบนี้ วรรณยุกต์ไทยขึ้นสูงถึงราว 1.03 em
ซึ่งเกินกรอบของฟอนต์ละตินเกือบทุกตัว อาการคือ **หัววรรณยุกต์โดนตัดเป็นเส้นตรง**

## 2. การตัดบรรทัด

ภาษาไทยไม่มีช่องว่างระหว่างคำ เอนจินส่วนใหญ่ตัดบรรทัดที่ช่องว่างเท่านั้น
ผลคือข้อความไทยยาว ๆ จะล้นกรอบหรือตัดกลางคำ

**ทางแก้: ใส่ U+200B (ZWSP) ระหว่างคำ**

- ห้ามใช้ช่องว่างจริง — ไทยไม่เว้นวรรคระหว่างคำ อ่านแล้วแปลกมาก
- ZWSP ตัดบรรทัดได้ แต่ไม่กินที่
- ตัดคำด้วย PyThaiNLP (`word_tokenize`) และเพิ่มพจนานุกรมคำเฉพาะของเกมเอง

**สำคัญ: อย่าเก็บ ZWSP ไว้ในไฟล์ต้นฉบับ**

ให้ไฟล์แปล (CSV หรือ JSON) สะอาด แล้ว **แทรก ZWSP ตอน build** เหตุผล:

- ZWSP มองไม่เห็น แก้ไฟล์ทีหลังแล้วพังโดยไม่รู้ตัว
- diff อ่านไม่รู้เรื่อง
- ตัววาลิเดตจับได้ว่ามีหลุดเข้ามา (ดูหัวข้อ 4.3)

**ต้องกันส่วนที่ห้ามแตะก่อนส่งเข้าตัวตัดคำ**: ตัวแปรในวงเล็บปีกกา, แท็กสี, ตัวคั่นบรรทัด

**จุดที่ห้ามมีจุดตัดบรรทัด** (เจอในเกมจริงตอนเทส):

- ห้ามใส่ ZWSP **ก่อน** `? ! . , ; : ) ] ” ’ ๆ ฯ` และ **หลัง** `( [ “ ‘` ไม่งั้นเครื่องหมายหล่นไปต้นบรรทัด
- ไม้ยมกที่เว้นวรรคหน้า (`เฉย ๆ`) ตัดบรรทัดที่ช่องว่างนั้นได้ ทำให้ `ๆ` ขึ้นบรรทัดใหม่โดด ๆ
  ตอน build ให้แทนช่องว่างหน้า `ๆ` ด้วย NBSP (U+00A0) และให้ฟอนต์ไทยรับ U+00A0 ด้วย
- PyThaiNLP หั่นชื่อทับศัพท์กลางคำ (อาร์·เชม) ให้ดึงคำไทยทุกคำจาก glossary ใส่ `custom_dict`
  (`Trie(set(thai_words()) | glossary_words)`)

## 3. ฟอนต์

### 3.1 รวมตัวอักษรไทยเข้าฟอนต์เดิมของเกม ไม่ใช่เอาฟอนต์ไทยมาแทน

เกมออกแบบ UI มาตามความกว้างและความสูงของฟอนต์เดิม ถ้าสลับฟอนต์ทั้งตัว ทุกอย่างจะเพี้ยน
วิธีที่ได้ผลคือเอา glyph ไทยไปใส่ในฟอนต์เดิม ตัวอักษรละตินไม่ขยับเลย

ขั้นตอน:

1. scale advance ของ glyph ไทยให้เข้ากับ units-per-em ของฟอนต์ปลายทาง
2. **decompose composite glyph** — ฟอนต์ไทยหลายตัวทำสระอำเป็น composite ซึ่งพังเมื่อข้ามฟอนต์
3. ลบตาราง per-glyph ที่ค้างมา (hdmx ฯลฯ) ไม่งั้นไฟล์ไม่ valid
4. `recalcUnicodeRanges`
5. ขยาย OS/2 Windows metrics (หัวข้อ 1.4)
6. เปลี่ยนชื่อ family

### 3.2 สัญญาอนุญาตฟอนต์ — จุดที่คนลืมแล้วเจ็บตอนปล่อย

**เรื่องนี้โปรเจกต์นี้เกือบปล่อยผิด จับได้ตอนเตรียมขึ้น Nexus**

| สัญญา | ข้อที่ต้องทำ |
|---|---|
| **SIL OFL 1.1 ข้อ 3** | ห้ามใช้ Reserved Font Name ของต้นฉบับ จึง **ต้องเปลี่ยนชื่อ family** |
| **SIL OFL 1.1 ข้อ 5** | งานดัดแปลง **ต้องเผยแพร่ภายใต้ OFL ทั้งก้อน** |
| **SIL OFL 1.1 ข้อ 2** | ต้องแนบ copyright notice และตัวสัญญาไปด้วย |
| **Apache 2.0 ข้อ 4(b)** | ต้อง **ระบุว่าไฟล์ถูกแก้** |

**กับดักที่เจอจริง:** ฟอนต์ฐานเป็น Apache 2.0 พอรวม Noto Sans Thai (OFL) เข้าไป
**ฟอนต์ที่ได้ต้องกลายเป็น OFL** ตามข้อ 5 — แต่ `name` table ยังประกาศ Apache 2.0 อยู่
และไม่มี copyright ของ Noto เลย ซึ่งผิดสัญญาถ้าปล่อยสาธารณะ

**เช็กลิสต์ก่อนปล่อย** — เปิด `name` table ดูจริง อย่าเดา:

```python
from fontTools.ttLib import TTFont
n = TTFont(path)["name"]
for i in (0, 1, 6, 13, 14):   # copyright, family, postscript, license, license URL
    print(i, n.getDebugName(i))
```

ต้องเห็น: copyright ของ **ทุกต้นทาง**, สัญญาที่เข้มที่สุดในบรรดาที่รวมกัน,
family ที่ไม่ใช่ชื่อสงวน, และข้อความบอกว่าไฟล์ถูกแก้

## 4. ไปป์ไลน์งานแปล

### 4.1 รูปแบบไฟล์ต้นฉบับ

ใช้ **CSV คอลัมน์เดียวกันทั้งโปรเจกต์**: `key, en, th, status, description, notes`

- `key` = คีย์ของเกม ใช้ join กับไฟล์เกมตอน build
- `en` = ข้อความต้นทาง เก็บไว้เทียบ **และตรวจจับว่าเกมอัปเดตแล้ว**
- `status` = `todo` / `changed` / `draft` / `reviewed`
  โดย `changed` คือคีย์เดิมแต่ `en` เปลี่ยน ต้องแปลใหม่ — ตัวนี้มีค่ามากตอนเกมอัปเดต
- `description` = คำอธิบายบริบทจากเกม ถ้าเกมมีให้ ใช้ประโยชน์ได้มาก

### 4.2 วงจรแปลเป็นชุด

```
export     ได้ batch-NNN.json   (รวมบริบทและศัพท์ที่เกี่ยวข้อง)
แปล        ได้ done-NNN.json    (คีย์ -> คำแปล)
apply      ตรวจทั้งชุดก่อน แล้วค่อยเขียน CSV
validate
commit
```

**กฎที่สำคัญที่สุด: apply ต้องตรวจให้ครบทั้งชุดก่อน แล้วค่อยแตะไฟล์**
ถ้ามีแถวเดียวผิด ให้ล้มทั้งชุดโดยไม่เขียนอะไรเลย
ไม่งั้นจะได้ CSV ที่เขียนไปได้ครึ่งทาง แล้วไม่รู้ว่าสถานะจริงคืออะไร

**จัดเรียงตามหมวดก่อนแบ่งชุด** — ลำดับคีย์ในไฟล์เกมมักสลับหมวดไปมา
ถ้าแบ่งชุดตามลำดับเดิมจะได้ชุดละ 1 แถวเต็มไปหมด แปลแล้วบริบทขาด
(โปรเจกต์นี้เคยได้ 250 ชุดจาก 457 แถว ก่อนจะแก้)

### 4.3 ตัววาลิเดต — ตรงนี้คือที่กันพัง

ต้องตรวจทุกแถวก่อนเขียน:

| ตรวจอะไร | ทำไม |
|---|---|
| **จำนวนตัวแปรตรงกับต้นฉบับ** | ตัวแปรหายไปตัวเดียว เกมแสดงค่าผิดหรือ crash |
| **ชื่อตัวแปรตรงกัน** | สลับตัวแปรแล้วตัวเลขไปโผล่ผิดที่ |
| **จำนวนและชนิดแท็กตรงกัน** | แท็กสีต้องครบคู่และจำนวนเท่าเดิม |
| **ไม่มี ZWSP** | ต้องมาจากขั้น build เท่านั้น |
| **ไม่ว่าง** | คำแปลหายไปเงียบ ๆ |
| **ไม่มีคีย์แปลกปลอม** | พิมพ์คีย์ผิดแล้วคำแปลไม่ถูกใช้โดยไม่มีใครรู้ |

ของจริงที่ตัวนี้จับได้ในโปรเจกต์นี้: แท็กสีไม่ครบคู่ 2 แถว ถ้าหลุดไปผู้เล่นจะเห็นแท็กดิบบนหน้าจอ

### 4.4 คลังศัพท์ (glossary)

ดึงศัพท์อัตโนมัติจากคีย์ที่ลงท้ายด้วย `_name` แล้วแปลครั้งเดียว ใช้ซ้ำทุกที่

- จับคู่แบบ **คำเต็มเท่านั้น** และ **เรียงจากคำยาวไปสั้น**
  ไม่งั้น "Attack" จะไปแทนที่ข้างใน "Attack Speed"
- แนบศัพท์ที่เกี่ยวข้องไปกับทุกชุดที่ export ออกไป
- แถวที่เป็นชื่อล้วนและตรงกับศัพท์เป๊ะ **เติมอัตโนมัติได้เลย**
  โปรเจกต์นี้เติมได้ 1,065 แถวโดยไม่ต้องแปลมือ
- อย่าลืมกวาด **ชื่อสกิลและความสามารถ** ด้วย ไม่ใช่แค่ชื่อไอเทม (รอบแรกตกไปราว 80 คำ)

### 4.5 งานหลายหมื่นบรรทัด — แปลขนานหลายเอเจนต์

ใช้กับ Bewitching Sinners (22,042 บรรทัด ราว 237,000 คำ) ด้วย workflow 5 ช่องทางพร้อมกัน
เอเจนต์ละ 4 ชุด ชุดละ 150 บรรทัด รวม 147 ชุด

- **STYLE.md ไฟล์เดียวเป็นสัญญา**: รูปแบบไฟล์ กฎเหล็ก ตารางเสียงตัวละคร (สรรพนาม หางเสียง
  วิธีเรียกผู้เล่น) คำหยาบ และ glossary ทุกเอเจนต์อ่านก่อนเริ่ม
- ไฟล์ชุดงาน `key|ผู้พูด|English` หนึ่งบรรทัดต่อหน่วย แทน escape ด้วย token (`<br>`, `<q>`)
  เพราะเครื่องมือเขียนไฟล์บางตัวกิน backslash ไฟล์ผลลัพธ์ `key|ไทย`
- ทุกเอเจนต์ต้องรันตัวตรวจกับไฟล์ตัวเองจนผ่านก่อนจบ แต่ **ห้าม apply/build** มีคนเดียวที่รวม
- **งานรอดอยู่บนดิสก์ ไม่ใช่ใน workflow**: ชนลิมิตการใช้งานกลางคัน (18 เอเจนต์ล้มพร้อมกัน)
  แก้โดยตรวจไฟล์ทุกชุดบนดิสก์ แล้วรันใหม่เฉพาะชุดที่ไม่มีไฟล์หรือไม่ผ่านตัวตรวจ
  ไฟล์ที่เขียนค้างครึ่งทางอาจมีแถวคีย์ผิด/ว่าง ตัวตรวจต้องจับ "คีย์ที่ไม่รู้จัก"
- **ศัพท์เพี้ยนข้ามเอเจนต์**: ให้ทุกเอเจนต์รายงานศัพท์ที่คิดเองเป็น `English => ไทย`
  แล้วนับรูปสะกดแต่ละแบบในไฟล์ผลลัพธ์ทั้งหมดก่อน build เจอราว 10 คู่ใน 22,000 บรรทัด
  (อิลฟ์/อิล์ฟ, ยาบ๊ายบายน้องแข็ง/ยานกเขาไม่ขัน) เลือกแบบเดียวแล้วแทนที่ทุกไฟล์
- ตัวตรวจเพิ่มที่คุ้ม: อักษร U+FFFD (ไฟล์ต้นทาง encoding พัง ต้องเขียน — หรือ ... แทน),
  อักษรจีนหลุด, `"` ตรง ๆ ในข้อความ, ไม้ยมกไม่เว้นวรรคหน้า, ตัวแปรสรรพนามต้องใช้รูป `!t`
- คำที่เป็น UI (ชื่อไอเทม ชื่อสูตรยา) ให้แปลชุดท้าย แล้วให้เอเจนต์ใช้คำที่บทพูดใช้ไปแล้ว

## 5. กฎการเขียนภาษาไทยสำหรับข้อความในเกม

### 5.1 สิ่งที่ห้ามแตะเด็ดขาด

- ตัวแปรทุกชนิด — คัดลอกมาทั้งก้อน ห้ามแปลข้างใน ห้ามเว้นวรรคเพิ่ม
- แท็กมาร์กอัป — จำนวนและชนิดต้องเท่าต้นฉบับเป๊ะ
- ตัวคั่นบรรทัดของเกม

### 5.2 ธรรมเนียมภาษาไทย

- **ใช้เลขอารบิก** (1 2 3) ไม่ใช้เลขไทย — คนไทยอ่านเลขอารบิกในเกมเป็นปกติ
- **พหูพจน์ไม่ต้องเปลี่ยนรูป** — คีย์พหูพจน์ใช้คำแปลเดียวกับเอกพจน์ได้เลย
- **เว้นวรรครอบคำอังกฤษและตัวเลขที่คงไว้** เช่น "ได้ พลังโจมตี 20%"
  แต่ **ไม่เว้นวรรคระหว่างคำไทยกับแท็กที่ต่อเป็นคำเดียวกัน** เช่น "ดู้ดนินจาได้"
- ระวังความยาว — ไทยมักสั้นกว่าอังกฤษ แต่ตัวอักษรสูงกว่า ระวังล้นกรอบแนวตั้ง

### 5.3 ข้อควรระวังที่เจอจริง

**ห้ามให้โมเดลเล็กหรือโมเดลถูกเขียนภาษาไทยเด็ดขาด**

โปรเจกต์นี้ใช้โมเดลถูกช่วยงานกลไก (ก๊อปไฟล์ คอมมิต) แต่ครั้งหนึ่งให้มันพิมพ์ไทย
ผลคือได้ **ตัวอักษรลาว** ปนมา และ **วรรณยุกต์ซ้อนสองตัว** ซึ่ง:

- มองด้วยตาเปล่าแทบไม่เห็นความต่าง
- ตัววาลิเดตจับไม่ได้ เพราะเป็นข้อความที่ถูกต้องตามรูปแบบทุกอย่าง
- ไปโผล่หน้าผู้เล่นจริง

กฎที่ตั้งไว้แล้วได้ผล: **ข้อความไทยทุกตัวมาจากโมเดลที่เก่งที่สุดเท่านั้น**
โมเดลถูกทำได้แค่งานกลไกที่ไม่แตะตัวอักษรไทย

**ความสม่ำเสมอของศัพท์สำคัญกว่าความสละสลวย**

ตัวอย่างจริง: `Thrown` เคยแปลว่า "ขว้าง" ในสองแถว แต่ "ขว้าง" ถูกใช้กับ `Shuriken Throw`
อยู่แล้ว กลายเป็นคนละสกิลที่ชื่อซ้ำกัน แก้เป็น "เหวี่ยง" ตาม glossary
**ให้ glossary เป็นคนตัดสิน ไม่ใช่ความรู้สึกตอนแปล**

## 6. การแจกจ่าย

### 6.1 อย่าแจกข้อความต้นฉบับของเกม

ถ้าปล่อยสาธารณะ **ห้ามใส่ข้อความอังกฤษของเกมลงในไฟล์ที่แจก** นั่นคือทรัพย์สินของผู้พัฒนา

วิธีที่ใช้ได้: แจกเฉพาะข้อความที่แปลแล้ว แล้วให้ **ตัวติดตั้งไปอ่านไฟล์ของผู้เล่นเอง**
มาเติมส่วนที่ยังไม่ได้แปล ผลลัพธ์เหมือนกันแต่ไม่มีการแจกจ่ายข้อความของเกม

> ข้อนี้ลามไปถึง repo ด้วย — ถ้า CSV ต้นฉบับมีคอลัมน์ `en` ครบทุกแถว
> **การ push repo ขึ้น public เท่ากับแจกข้อความของเกม**
> ต้องแยกส่วนที่เปิดได้ (เครื่องมือ, ตัวติดตั้ง) ออกจากข้อมูลแปล

### 6.2 ตัวติดตั้งที่แก้ไฟล์เกม

- **สำรองไฟล์เดิมก่อนแตะอะไรทั้งนั้น** และเก็บ SHA-256 ไว้ด้วย
- เขียนแบบ atomic (เขียนไฟล์ชั่วคราวข้าง ๆ แล้ว replace) กันไฟล์พังครึ่งทางตอนไฟดับ
- ล็อกกันรันซ้อน (เปิดไฟล์แบบ exclusive)
- ตรวจ hash ของไฟล์ต้นทางอีกครั้ง **ก่อน** สำรอง ไม่งั้นอาจสำรองไฟล์ที่ถูกม็อดแล้วทับของจริง
- ถอนการติดตั้งต้องคืนไฟล์ **ตรงทุกไบต์** ตรวจด้วย SHA-256 แล้วบอกผู้ใช้
- **ข้อความใน console ให้เป็นภาษาอังกฤษ** — console ของ Windows วาดสระและวรรณยุกต์ไทยเพี้ยน
  ส่วน README แยกไฟล์ค่อยเป็นไทย

### 6.3 เรื่องที่ไม่มีใครเตือนล่วงหน้า

**สคริปต์ติดตั้งจะโดนระบบสแกนกัก**

Nexus Mods กักไฟล์ของโปรเจกต์นี้ทันทีที่อัปโหลด เพราะมีไฟล์ .bat และ .ps1
โดยเฉพาะแฟล็ก ExecutionPolicy Bypass ซึ่งเป็นรูปแบบที่มัลแวร์ใช้ประจำ
แต่ **ตัดออกไม่ได้** เพราะไฟล์ที่โหลดจากเน็ตติด Mark of the Web
ถ้าไม่มีแฟล็กนี้สคริปต์จะไม่ยอมรันบนเครื่องผู้ใช้ส่วนใหญ่

เตรียมไว้ล่วงหน้า:

- สแกน VirusTotal เองแล้วเก็บลิงก์
- เขียนรายการไฟล์ทุกบรรทัดพร้อมขนาดและชนิด
- เขียนรายการ **ทุกพาธที่สคริปต์เขียน** ให้ครบ รวมไฟล์ชั่วคราวและไฟล์ล็อก
- ยืนยันได้ว่า: ไม่ต่อเน็ต ไม่แตะ registry ไม่เขียนนอกโฟลเดอร์เกม ไม่ต้องใช้สิทธิ์แอดมิน
- **ตรวจคำกล่าวอ้างพวกนี้กับโค้ดจริงก่อนส่งให้ผู้ตรวจ** (grep หา Invoke-WebRequest,
  Start-Process, Registry, TEMP, FromBase64) อย่าส่งคำรับรองที่ยังไม่ได้พิสูจน์

**ชื่อไฟล์ซ้ำกันทำผู้ใช้สับสน**

install.bat กับ install.ps1 อยู่โฟลเดอร์เดียวกัน พอ Windows ซ่อนนามสกุล
ผู้ใช้เห็น "install" สองบรรทัด ไม่รู้จะกดอันไหน — ย้าย .ps1 ลงโฟลเดอร์ย่อย scripts แก้ได้

**ฟอร์มบนเว็บกินแบ็กสแลช**

พาธที่มีแบ็กสแลชกลายเป็นคำติดกันในคำอธิบายบนหน้ามอด
ใช้สแลชปกติในข้อความที่ไปอยู่บนเว็บ

### 6.4 ตัวติดตั้งที่ใช้ runtime ของเกมเอง (Ren'Py)

- Ren'Py แจก Python มากับเกม: `lib/py3-windows-x86_64/python.exe`, `lib/py3-linux-x86_64/python`,
  `<Game>.app/Contents/MacOS/python` ให้ `install.bat` / `install.sh` เรียกตัวนี้รันสคริปต์ติดตั้ง
  ผู้เล่นไม่ต้องลงอะไรเพิ่ม และไม่ต้องใช้ PowerShell / ExecutionPolicy Bypass เลย
- string table ต้องมี `old "<ภาษาอังกฤษ>"` → แจกเฉพาะไทยในรูป `md5(ค่าสตริงอังกฤษ) -> ไทย`
  ตัวติดตั้งสแกน string literal ทุกตัวใน `.rpy`/`.rpym` ของเกม ใน `.rpa` และใน `renpy/common`
  ถอด escape แล้ว hash เทียบ ตัวที่ตรงค่อยเขียน `old`/`new` ลงเครื่องผู้เล่น และรายงานจำนวนที่จับคู่ได้
  (ไฟล์บทพูด `translate thai <id>:` แจกตรงได้ เพราะมีแค่ id รหัสผู้พูด และข้อความไทย)
- ก่อนแพ็ก: สแกนว่าข้อความต้นฉบับทุกบรรทัดที่ยาว 12 ตัวอักษรขึ้นไปไม่อยู่ในไฟล์ใดของ zip
- ถอนการติดตั้งลบเฉพาะสิ่งที่มี marker ของม็อด (ไฟล์ marker ในโฟลเดอร์ หรือบรรทัดหัวไฟล์)
- ทดสอบตัวติดตั้งจริง: แตก zip ลงเกม รัน install เทียบผลกับ build ที่ทำเอง (ต้องตรงทุกบรรทัด)
  แล้ว uninstall และเปิดเกมทั้งที่ค่าภาษาที่บันทึกไว้ยังเป็นไทย

### 6.5 Nexus Mods

- **ตรวจก่อนว่ามีหน้าเกมบน Nexus** ถ้าไม่มี ต้องขอให้เพิ่มเกมก่อนจึงอัปโหลดได้ (ใช้เวลา)
- ไฟล์ `.bat`/`.sh` โดนกักอัตโนมัติเสมอ แม้ไม่มี PowerShell อีเมล support พร้อมข้อมูลนี้:
  ไม่มี compiled code / ไม่มี zip ซ้อน, เนื้อหา `.bat` ทั้งไฟล์, สิ่งที่ตัวติดตั้งทำและไม่ทำ,
  ทุก path ที่เขียน, รายชื่อไฟล์พร้อมขนาดและ SHA-256
- SHA-256 ต้องตรงกับไฟล์ที่อัปโหลดจริง ออกเวอร์ชันใหม่ต้องสร้างรายการใหม่
- เปิดเผยว่าใช้ AI ช่วยแปลในเครดิต และติ๊กเนื้อหาผู้ใหญ่ถ้าเกมเป็น 18+

## 7. กับดักเครื่องมือ (Windows + Claude Code)

| ปัญหา | ทางแก้ |
|---|---|
| เครื่องมือเขียนไฟล์แปลง backslash escape เป็นอักขระจริง | เขียนไฟล์ผ่านสคริปต์ Python ใช้ `chr(92)` หรือใช้โทเคนแทนแล้วค่อยแทนที่ |
| Bash tool แปลง `>nul` เป็น `/dev/null` และกินแบ็กสแลช | สร้างไฟล์ .bat ผ่านสคริปต์ Python อย่าพิมพ์ตรงใน heredoc |
| heredoc แตกเมื่อเนื้อหายาวหรือมีอักขระพิเศษ | ใช้เครื่องมือเขียนไฟล์โดยตรง หรือเขียนผ่าน Python |
| `#` ในสตริง Python ถูกตัดใน heredoc | ใช้ `chr(35)` |
| pytest บน Windows ขึ้น "access violation" ปลอมเมื่อรัน PowerShell เยอะ | `addopts = -p no:faulthandler` |
| ไพป์ผลลัพธ์ pytest เข้า `tail` แล้ว exit code หาย commit ผ่านทั้งที่เทสต์ตก | อย่าไพป์ หรือต่อ `; echo "EXIT=$?"` |
| `.ps1` ต้องมี UTF-8 BOM ถึงจะอ่านภาษาไทยถูก | ถ้าเนื้อในเป็น ASCII ล้วนก็ไม่ต้องห่วง |
| ตัวแปร PowerShell ไม่สนตัวพิมพ์ใหญ่เล็ก | ตั้งชื่อให้ต่างกันจริง |
| เทสต์ที่ก๊อปโฟลเดอร์เกมจริงจะพังถ้ามอดติดตั้งค้างอยู่ | ให้เทสต์ skip เองเมื่อตรวจพบว่าถูกม็อดแล้ว |
| Bash heredoc ยุบ backslash คู่ให้เหลือตัวเดียว แม้ใช้ `<<'EOF'` (regex `[^"\\]` กลายเป็น `[^"\]`) พังเงียบ ๆ | สร้าง backslash ด้วย `chr(92)` หรือเขียนไฟล์ .py ด้วย Write tool |
| Python ของระบบพิมพ์ไทยลง console แล้ว `UnicodeEncodeError` (cp1252) | `sys.stdout.reconfigure(encoding='utf-8')` |
| shell ค้าง cwd อยู่ในโฟลเดอร์ที่จะลบ → `PermissionError` ตอน rmtree | `cd` ออกก่อน หรือใช้ path เต็ม |

## 7.5 Unity (TextMeshPro + Unity Localization + Addressables) — บทเรียนจาก DiceVaders

โปรเจกต์ที่สอง: DiceVaders (Unity 6000.3, IL2CPP, 1,575 ข้อความ) (โค้ดของโปรเจกต์นี้ไม่ได้รวมมาในสกิล)

### หาช่องข้อความ

- ดู `DiceVaders_Data/ScriptingAssemblies.json` ถ้ามี `Unity.Localization.dll` และ `Unity.TextMeshPro.dll`
  ข้อความจะอยู่ใน `StreamingAssets/aa/<platform>/localization-string-tables-<locale>_*.bundle`
  และคีย์อยู่ใน `localization-assets-shared_*.bundle` (m_Entries: m_Id -> m_Key)
- อ่าน/เขียนด้วย UnityPy (`read_typetree` / `save_typetree` / `env.file.save(packer="lz4")`)
  bundle มี typetree ให้ แต่ `resources.assets` ของ player build **ไม่มี typetree สำหรับ MonoBehaviour**
  (แก้ได้แค่ object native เช่น Font)
- แทนตาราง `en` ไปเลยง่ายที่สุด เพิ่ม locale ใหม่ต้องแก้ catalog เยอะ ไม่คุ้ม
  ตาราง en อาจมี entry ที่ไม่มีคีย์ใน shared data (ใช้ไม่ได้อยู่แล้ว) ให้ข้ามไป
- ข้อความ Unity Localization มี **ขึ้นบรรทัดจริง** ปนกับ `\n` แบบตัวอักษร ตัววาลิเดตต้องนับทั้งสองแบบ

### Addressables ตรวจ CRC

- bundle ที่ repack แล้ว CRC ไม่ตรง เกมจะโหลดไม่ขึ้น ต้อง patch `aa/catalog.bin` (binary catalog, Addressables 2.x)
- ในแต่ละ record ของ AssetBundleRequestOptions ฟิลด์ `[crc u32][size u32]` จะตามด้วยไบต์คงที่
  ชุดเดียวกันทุก record (เกมนี้คือ `05 9f 00 00 46 9f 00 00`) หาตำแหน่งจากขนาดไฟล์เดิม
  (ขนาดไม่ซ้ำกัน ตรวจว่าเจอที่เดียว) แล้วเขียน CRC = 0 กับขนาดใหม่
- `catalog.hash` ไม่ต้องแตะ ใช้กับ remote catalog เท่านั้น

### ฟอนต์

- **ไล่ดูฟอนต์ทุกตัวของเกมก่อน** อาจมีฟอนต์ไทยอยู่แล้ว เกมนี้ใช้ Chakra Petch (มีไทยครบ 87 ตัว)
  แบบนั้นอบ PUA ลงฟอนต์ของเกมเองได้เลย ไม่ต้องรวมฟอนต์อื่น ไม่มีปัญหาเรื่องรวมสัญญาอนุญาต
- TMP font asset แบบ dynamic (m_AtlasPopulationMode = 1) วาดจาก `Font.m_FontData` ตอนรัน
  แค่เปลี่ยนไบต์ TTF ใน Font object ก็พอ ไม่ต้องสร้าง SDF atlas เอง
- **ฟอนต์ตัวเดียวกันมีหลายสำเนา**: ใน bundle ของ Addressables และใน `resources.assets`
  (ฉากแรก level0 ใช้ชุดหลัง) ต้องแก้ทุกสำเนา ไม่งั้นบางหน้าจอยังพัง
- TMP ใน Unity 6 **ยังไม่ทำ GSUB และไม่วางตำแหน่ง mark ให้ไทย** วรรณยุกต์ทับสระบน ต้องอบ PUA เหมือนเดิม
- HarfBuzz อาจคืน offset เป็น 0 ทั้งหมด เพราะฟอนต์ใช้ GSUB เปลี่ยนเป็น glyph `.small` / `.narrow` แทน
  ยังต้องอบ PUA อยู่ดี เพราะ glyph พวกนั้นไม่มี code point
- **ช่วง PUA ชนกับฟอนต์อื่นใน fallback chain** ฟอนต์ Inter ของเกมใช้ U+E000–E2DC
  TMP ไปหยิบ glyph จาก Inter ก่อน คำไทยกลายเป็นตัว G Ĝ Ǵ
  ก่อนเลือกช่วง ให้สแกน cmap ของ **ทุก** ฟอนต์ในเกมแล้วเลือกช่วงที่ว่างจริง (เกมนี้ใช้ U+E300–EDFF)
- ฟอนต์หัวข้อที่ไม่มีไทย ให้เพิ่มฟอนต์ไทยต่อท้าย `m_FallbackFontAssetTable` ของ TMP font asset
- PUA ชุดเดียวกันต้องใช้ได้ทุกน้ำหนักฟอนต์: เลือกช่องจาก Regular แล้วให้แต่ละน้ำหนัก
  shape run เดียวกันด้วยเส้นของตัวเอง (`bake_texts` คืน run + ลำดับกลุ่ม แทนชื่อ glyph)
- U+200B ใช้ได้ใน TMP (ใส่ glyph ความกว้าง 0 ลงฟอนต์ด้วย)
- ห้ามใส่ ZWSP ในช่วง `<nobr>...</nobr>`

### ทดสอบในเกมเองโดยไม่ต้องให้ผู้ใช้ช่วย

- แคปจอด้วย PowerShell + `System.Drawing` (ต้องเรียก `SetProcessDPIAware` ก่อน ไม่งั้นได้ภาพครึ่งจอ)
- คลิกด้วย `SetCursorPos` + `mouse_event` หลัง `AppActivate` หน้าต่างเกม
  (`tools/shot.ps1`, `tools/click.ps1` ในโปรเจกต์ DiceVaders)
- **แค่เลื่อนเมาส์ไปชี้ (SetCursorPos) ไม่ทำให้ทูลทิปของ Unity ขึ้น ต้องคลิก**
- เปิดเกมผ่าน `steam://rungameid/<appid>` (appid อยู่ใน `steamapps/appmanifest_*.acf`)
- ตอนทดสอบ spike ให้ใส่ข้อความทดสอบลงทุกแถวที่ยังไม่ได้แปล จะเห็นทุกฟอนต์ในหน้าจอเดียว
- ซูม + autocontrast ภาพก่อนตัดสิน ข้อความจาง ๆ หลอกตาได้

### การแปล

- ชื่อเฉพาะ (ยูนิต อาร์ติแฟกต์ ผู้บัญชาการ) คงภาษาอังกฤษ ทำให้เติมอัตโนมัติได้ 386 แถว
  และผู้เล่นค้นวิกิได้ เก็บเป็นสถานะ `keep` (th == en)
- คีย์ Unity Localization เรียงคำนำหน้าเป็นหมวดอยู่แล้ว (`_Keyword`, `_Title`, `_Desc`, `_Misc`)
  เรียงตามหมวดก่อนแบ่งชุด
- แปลคีย์เวิร์ด (`*_Keyword`) ก่อน เพราะ `{k.X}` ในประโยคจะถูกแทนด้วยคำพวกนั้น

### กับดักเครื่องมือ

## 7.6 Ren'Py 8 — บทเรียนจาก Bewitching Sinners

โปรเจกต์ที่สาม: visual novel บน Ren'Py 8.3.7 (Python 3) บทพูด 20,113 บรรทัด + ข้อความ UI 1,929 รายการ
โค้ดอ้างอิงอยู่ในโฟลเดอร์ `renpy/` ข้างสกิลนี้

### การแสดงผล — ไม่ต้องอบ PUA

- Ren'Py 8 ใช้ HarfBuzz เป็นค่าเริ่มต้น (`style.default.shaper = "harfbuzz"` บน Python 3)
  วรรณยุกต์ซ้อนสระบนถูกต้องเอง **แต่ยังต้อง spike** เพราะบาง style อาจตั้ง `shaper "freetype"`
- ใช้ `FontGroup` ส่งเฉพาะ U+0E00–0E7F, U+200B–200D และ U+00A0 ไปฟอนต์ไทย ที่เหลือใช้ฟอนต์เดิมของเกม
  ตัวอักษรละตินหน้าตาไม่เปลี่ยน และไม่ต้องรวมฟอนต์ จึงไม่ต้องเปลี่ยนชื่อ family (แนบไฟล์ OFL ก็พอ)
- ตั้งฟอนต์ใน `translate thai python:` ที่ `gui.text_font`, `gui.name_text_font`, `gui.interface_text_font`
- Ren'Py ไม่ตัดคำไทยเอง ตัดเฉพาะที่ช่องว่างและ ZWSP ใส่ ZWSP ตอน build เหมือนเอนจินอื่น

### หาข้อความทั้งหมด

- สร้าง template ที่ id ตรงกับเกมเวอร์ชันนี้ด้วย Python ของเกมเอง ไม่ต้องมี SDK:
  `lib/py3-windows-x86_64/python.exe <Game>.py . translate thai`
  แล้วย้ายโฟลเดอร์ `game/tl/thai` ที่ได้ออกไปเป็น template (อย่าทิ้งไว้ในเกม)
- template ให้บทพูดครบ แต่ `translate thai strings` มีเฉพาะ `_()` ที่หาเจอในไฟล์ .rpy นอก archive
  ต้องสแกนเพิ่มเอง: ชื่อใน `Character('...')`, ตัวแปรชื่อผู้พูด (`NPC = "..."` ของ `DynamicCharacter`),
  ฟังก์ชันแชท/ข้อความที่เกมเขียนเอง (`msg("...")`), `'name': "..."` ของตัวเลือก, และสคริปต์ใน `.rpa`
- คำแปลภาษาอื่นที่มีอยู่แล้ว (`tl/chinese`) เป็นแหล่งรายชื่อ string ที่คนแปลก่อนหน้าหาเจอ
  ใช้เฉพาะ `old` ที่ยังมีอยู่ในซอร์สจริง
- อ่าน `.rpa` (RPA-3.0) ได้เอง: บรรทัดแรกมี offset กับ key, index เป็น zlib + pickle,
  ตำแหน่งแต่ละไฟล์ XOR ด้วย key

### โค้ดเกมที่ผูกภาษาไว้

- `if _preferences.language == None: <ภาษาอังกฤษ> else: <ภาษาจีน>` → ภาษาไทยได้กิ่งภาษาจีน
  ทางแก้ที่ไม่ต้องแก้ไฟล์เกม: เพิ่ม string entry ที่ `old` เป็นข้อความจีนพวกนั้นแล้ว `new` เป็นไทย
  (จับคู่จีน↔อังกฤษจากกิ่งเดียวกันในซอร์ส แล้วใช้คำแปลของอังกฤษ)
- ตัวแปรที่เก็บคำ เช่น สรรพนาม (`kamu = "她"`) → ในคำแปลไทยใช้ `[kamu!t]` แล้วเพิ่ม string entry
  `old "她" new "เธอ"` (`!t` = แปลค่าตัวแปรผ่าน string table ตอนแสดงผล)
- ข้อความที่ประกอบตอนรัน เช่น `"%s. %s" % (n, name)` หรือ typewriter ที่ตัดสตริงทีละตัว
  ไม่มีทางตรงกับ string table → แปลตอนสร้าง object โดย patch `__init__` ของคลาส
  **อย่า** rebind ฟังก์ชันใน store (เช่น `store.msg = ...`) เพราะจะหายตอนกลับเมนูหลัก และอาจถูก pickle ลงเซฟ
- สตริงอังกฤษเดียวกันมีสองความหมาย ("Quill" เป็นทั้งชื่อตัวละครและไอเทมปากกาขนนก)
  string table เลือกได้ความหมายเดียว → ให้ string table ใช้ความหมายไอเทม แล้วเปลี่ยน `quil.name`
  ใน `config.change_language_callbacks` + `config.language_callbacks[lang]`
- ตรวจหาความหมายซ้ำแบบนี้: เทียบคำแปลของชื่อผู้พูดทุกตัวว่ายังเป็นชื่อคน

### ฟอนต์ที่ฝังในหน้าจอ

- หน้าจอแชท ร้านค้า และ **หน้าจอของ Ren'Py เอง** (error screen, Shift+G renderer, accessibility)
  ระบุฟอนต์ตรง ๆ ไม่ผ่าน gui → ไทยเป็นกล่องสี่เหลี่ยม
- แก้ทั้งหมดด้วย `config.font_name_map["NotoSansSC-Regular.ttf"] = FontGroup(...)` (รวม `DejaVuSans.ttf`,
  `DejaVuSans-Bold.ttf`) map ถาวรได้ ภาษาอื่นหน้าตาไม่เปลี่ยนเพราะตัวละตินยังใช้ฟอนต์เดิม
- **สร้าง FontGroup ก่อนแล้วค่อย map ชื่อ** — `FontGroup.add()` โยน `FontGroup do not accept font aliases`
  ถ้าชื่อฟอนต์อยู่ใน `font_name_map` แล้ว ถ้าต้องอ้างกลุ่มเดิมทีหลัง ให้อ่านจาก `config.font_name_map[...]`

### `config.defer_tl_scripts = True` — กับดักใหญ่ที่สุด

เกมที่ตั้งค่านี้จะโหลด `game/tl/<ภาษา>/` **เฉพาะตอนภาษานั้นถูกเลือก** และโหลดหลังจาก Ren'Py
สำรอง store ไว้แล้ว ผลที่เจอจริง:

1. ปุ่มเลือกภาษาที่อยู่ใน `tl/thai` **ไม่ปรากฏ** สำหรับผู้เล่นที่เปิดเกมเป็นภาษาอังกฤษ
   (เครื่องผู้พัฒนาไม่เจอ เพราะตั้งเป็นไทยค้างไว้) → ไฟล์ปุ่มต้องอยู่ใน `game/` เช่น
   `game/thaimod_language_button.rpy` ปุ่มเรียก `Language("thai")` ซึ่งโหลด `tl/thai` เอง
2. ชื่อที่ init code ใน `tl/thai` สร้างไว้ใน store **หายตอนกลับเมนูหลัก/เริ่มเกมใหม่** (clean stores)
   แล้ว `translate thai python` ที่รันซ้ำก็ `NameError` → เก็บของที่ต้องอยู่ถาวรไว้ใน `config`
   (`font_name_map`, รายการ callback), attribute ของคลาส หรือเขียนแบบ inline ใน `translate python`
3. ปุ่มที่ต้องแสดงในหน้าตั้งค่าโดยไม่แก้ `screens.rpy` ของเกม: เพิ่มชื่อ screen ใน
   `config.always_shown_screens` แล้ว screen นั้นแสดงเฉพาะเมื่อ `renpy.get_screen("preferences")`
   ใส่ `{font=...}` ให้ข้อความปุ่มเพราะตอนเป็นภาษาอังกฤษยังไม่มี FontGroup ไทย

### ทดสอบในเกมแบบไม่ต้องคลิก (test harness)

- ไฟล์ชั่วคราว `game/zz_thai_spike.rpy` ที่ทำงานเฉพาะเมื่อมี environment variable:
  `label splashscreen` → `renpy.change_language("thai")` → `renpy.jump(label)`
- `config.periodic_callbacks` เรียก `renpy.screenshot()` ทุก N วินาทีแล้ว `renpy.quit()`
- `config.label_overrides = {"piko": "cewe"}` ข้ามหน้าจอที่ต้องคลิก (เช่นหน้าเลือกตัวละคร)
- auto-forward: `_preferences.afm_enable = True` แต่ `renpy.pause()` ที่ไม่มีเวลาจะค้างรอคลิก
  ทดสอบโค้ดแบบนั้นด้วยการสร้าง object ตรง ๆ แทนการเรียกฟังก์ชันที่ pause
- เคสที่ต้องรันทุกครั้งก่อนปล่อย:
  - เปิดเกมเป็น **ภาษาอังกฤษ** แล้วตรวจว่าปุ่มไทยมีอยู่ (`renpy.has_screen`) และกดแล้วเปลี่ยนได้
  - `renpy.full_restart()` (กลับเมนูหลัก) ขณะเป็นไทย ต้องไม่มี traceback
  - `renpy.save()` ขณะเป็นไทย แล้ว `renpy.unlink_save()` ลบทิ้ง
  - หน้าจอแชท/ตัวเลือก/หน้าตั้งค่า/เมนูในเกม และ `renpy.show_screen("_choose_renderer")`
- `<python ของเกม> <Game>.py . compile` ตรวจว่าไฟล์ .rpy คอมไพล์ผ่าน (exit 0 และไม่มี errors.txt ใหม่)
- หน้าต่าง Ren'Py ที่ไม่ได้โฟกัสจะกินคลิกแรก: คลิกจริงต้องสองครั้ง การทดสอบผ่าน harness เชื่อถือได้กว่า

### เกมที่ให้ผู้เล่นเลือกเพศ

- ตัวละครผู้เล่นใช้ "ฉัน" และหางเสียงที่ไม่ระบุเพศ (นะ น่ะ เถอะ ล่ะ สิ) ห้าม ครับ/ค่ะ
- สรรพนามบุรุษที่สามของผู้เล่นใช้ตัวแปรของเกมผ่าน `!t` ภาษาไทยไม่ผันรูป ตัวแปรสามตัว
  (she/her/hers) ใช้ตัวเดียวกันได้: `[kamu!t]` → เธอ / เขา
- คนอื่นเรียกผู้เล่นว่า "เธอ" (กลาง ๆ) หรือ "แก" (หยาบ) ใส่ไว้ในตารางเสียงตัวละครของ STYLE.md

## 8. สรุปสั้น ๆ ถ้าอ่านได้แค่หัวข้อเดียว

1. **พิสูจน์การแสดงผลก่อนแปล** — ใส่ "ที่ ปี่ ฝี ปู่" เข้าเกมวันแรก

3. ใส่ ZWSP ตอน build เท่านั้น อย่าเก็บลงไฟล์ต้นฉบับ
4. ตรวจจำนวนตัวแปรและแท็กให้ครบ **ก่อน** เขียนไฟล์ ล้มทั้งชุดถ้ามีผิด
5. glossary เป็นคนตัดสินเรื่องศัพท์ ไม่ใช่ความรู้สึกตอนแปล
6. ข้อความไทยมาจากโมเดลที่เก่งที่สุดเท่านั้น
7. เปิด `name` table ตรวจสัญญาอนุญาตฟอนต์ก่อนปล่อย
8. อย่าแจกข้อความต้นฉบับของเกม ให้ตัวติดตั้งไปอ่านจากเครื่องผู้เล่น
9. เตรียมเอกสารตอบระบบสแกนไว้ล่วงหน้า สคริปต์ติดตั้งโดนกักแน่
10. เลือกช่วง PUA หลังสแกน cmap ของทุกฟอนต์ในเกม และแก้ฟอนต์ทุกสำเนา (Unity: bundle + resources.assets)
11. ค้นหาฟอนต์ที่ฝังในทุกหน้าจอ รวมหน้าจอของเอนจินเอง ไม่ใช่แค่ค่าใน GUI config
12. ทดสอบจากสถานะผู้เล่นใหม่ (เปิดเกมเป็นภาษาอังกฤษ) + กลับเมนูหลัก + เซฟ ไม่ใช่แค่สถานะที่พัฒนาอยู่
13. งานใหญ่: STYLE.md ไฟล์เดียว, งานรอดบนดิสก์, รันใหม่เฉพาะชุดที่ขาด, ปรับศัพท์ที่สะกดต่างกันก่อน build
14. ถ้าเกมแจก runtime มาเอง (Ren'Py = Python) ให้ตัวติดตั้งใช้ตัวนั้น
